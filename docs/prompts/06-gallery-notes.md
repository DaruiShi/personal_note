# Vibe-coding prompt — gallery notes with AI-generated titles and tags

Paste everything between the `====` markers into your coding agent.

**Context you must respect.** The repo already has one structured note kind, `timeline` (`lib/timeline.js`,
`public/timeline.js`, kind branching in `server.js`, `lib/llm.js` for MiniMax). Gallery is the second structured
kind, so this work **extends** that machinery - it must not fork it. Read `lib/timeline.js`, `public/timeline.js`,
the timeline branches in `server.js` (`server.js:953-1042`), and `lib/llm.js` before writing anything.

**The load-bearing design decision, same as timeline.** For a gallery note, `note.gallery.items` is the single
source of truth and `note.content` is a **derived markdown mirror** regenerated by the **server** on every write.
That keeps search, export, version history, public share links, trash and conflict detection working with no
changes. Never store gallery data in `content`, and never let a client-supplied `content` overwrite the mirror.

====

## Task

Add a `gallery` note kind: cards in a responsive grid, each with a colour, a title and a text preview. Clicking a
card opens a detail view with the full content. Cards can be dragged to reorder, tagged individually, and recoloured.
Adding a card with an empty title or empty tags asks the server to call MiniMax M3.1-Flash to generate them.

## Hard constraints

- **Zero npm dependencies.** Node stdlib only; no bundler, framework or TypeScript on the web.
- **No inline script.** CSP is `script-src 'self'`. New browser code is a same-origin file under `public/`.
- **The API key never reaches a client.** It stays in `config.json`, read once by `lib/llm.js`, never returned, never
  logged. The suggest endpoint must never echo it or the upstream request.
- **Do not repeat a mistake that is already fixed in `lib/llm.js`.** `MiniMax-M3.1-Flash` **requires adaptive
  thinking** and rejects `{"type":"disabled"}` with HTTP 400. `lib/llm.js` therefore sends no `thinking` field by
  default and budgets `maxCompletionTokens: 4096` for reasoning headroom (`lib/llm.js:14-29`). Reuse that; do not
  "optimise" by disabling thinking.
- **Do not break the timeline, markdown, or the shipped Android app (v1.19).** Every existing test must pass
  unchanged.
- **Match the existing style:** result objects `{ok:false, code, message}` from `lib/*.js`, thin `server.js` handlers
  that convert them to HTTP, UMD browser modules (`window.NotesX` + `module.exports`), `node:test` coverage.

## 1. Data model

```
note.kind    : 'markdown' | 'timeline' | 'gallery'   (absent = 'markdown')
note.gallery : { items: [ GalleryCard ] }            (only when kind === 'gallery')
```

```
GalleryCard = {
  id:        string,        // UUID, server-assigned when absent
  title:     string,        // 1..200 chars - never empty after normalisation (see 2.2)
  content:   string,        // 1..4000 chars, plain text
  tags:      string[],      // 0..10, each 1..32 chars, no leading '#'
  color:     string,        // one of the 12 palette keys in 2.3
  createdAt: number,
  updatedAt: number
}
```

**Array order is the display order.** Reordering means rewriting the `items` array in the new order; there is no
separate `position` field (this matches how folders already store manual order).

## 2. `lib/gallery.js` - server-side pure module

Model it on `lib/timeline.js`: stdlib only, `{ok, ...}` / `{ok:false, code, message, index}` results, covered by
`node:test`.

```
GALLERY_KIND = 'gallery'
MAX_ITEMS = 500
MAX_TITLE = 200
MAX_CONTENT = 4000
MAX_TAGS = 10
MAX_TAG_LEN = 32
MAX_MIRROR_BYTES = 1024 * 1024
PALETTE = ['amber','rose','violet','indigo','sky','teal',
           'emerald','lime','orange','fuchsia','slate','sand']   // exactly 12
```

### 2.1 `normalizeGallery(raw, opts)`

Accepts `raw` (`{items}` or an array), returns `{ok:true, items, markdown}` or
`{ok:false, code, message, index}`. Rules:

- Preserve the incoming array order exactly (this is the drag order).
- `items` must be an array; more than `MAX_ITEMS` -> `{code:'too_many_items'}`.
- Per item, in order, with `index` in the error:
  - skip non-objects silently;
  - `content`: must be a string after trim, non-empty -> else `{code:'invalid_item_content'}`; truncate to
    `MAX_CONTENT`;
  - `title`: string, trimmed, truncated to `MAX_TITLE`; **when empty, fill with `fallbackTitle(content)`** (2.2);
  - `tags`: accept an array of strings or a single comma/space separated string; strip a leading `#`, trim, drop
    empties, dedupe case-insensitively keeping first spelling, truncate each to `MAX_TAG_LEN`, cap at `MAX_TAGS`;
  - `color`: keep it when it is a palette key, otherwise assign `nextColor(items, rand)`;
  - `id`: keep when UUID-shaped and unique within the note, else assign `crypto.randomUUID()`;
  - timestamps: keep finite positive numbers, else `Date.now()`.
- Build the markdown mirror with the same normalised items.

`opts` carries `{ rand }` so tests can inject a deterministic random source (default `crypto.randomInt`).

### 2.2 `fallbackTitle(content, maxWords = 9)`

Deterministic, no LLM: collapse whitespace, take the first sentence (split on `.`/`。`/`!`/`?`/`！`/`？`/newline),
then the first `maxWords` whitespace-separated words (for CJK content with no spaces, take the first 24 characters),
strip a trailing `…`/punctuation, append `…` only when truncated, and never return an empty string (`Untitled card`
as the last resort). Used server-side on normalisation and client-side when the LLM is unavailable, so **both copies
must agree** - export it from `public/gallery.js` too and add a parity test.

### 2.3 `nextColor(items, rand)`

Pick the palette key that is used **least** among the note's current cards, with `rand` breaking ties - so a new
card looks randomly coloured but never duplicates the colour of every card around it. Falls back to
`PALETTE[rand(len)]` when `items` is empty.

### 2.4 `galleryToMarkdown(items)`

Deterministic mirror, and the contract you must unit-test exactly:

```
## {title}

{content}

Tags: a, b

---

## {next title}
...
```

- Cards separated by a blank line plus `---` plus a blank line, **not** after the last card.
- The `Tags:` line is omitted entirely when a card has no tags.
- Do not escape markdown inside `content`; it is plain text that may legitimately contain markdown, and the mirror
  is what makes search and the public share page readable.
- Collapse newlines inside `content`? **No** - keep the author's paragraphs; only trim leading/trailing whitespace.

### 3.3 `PUT /api/notes/:id`

### 3.6 `POST /api/gallery/suggest`

Generate a title and/or tags for one card's content. Add it next to the timeline parse route
(`server.js:1158-1204`) and follow its structure precisely:

- Auth: the global session gate already covers it.
- `503 {code:'llm_not_configured'}` when `!llmConfig`.
- **Separate** rate-limit buckets from the timeline route, because this is called per card: `suggestHits` (per user,
  sliding hour, cap `llmConfig.suggestPerHourPerUser`, default **60**) and `suggestInFlight` (global cap 2 ->
  `503 {code:'busy'}`). Do not share `parseHits`/`parseInFlight`; gallery use must not starve timeline parsing.
- `readJson(req, 64 * 1024)`. Body: `{ content, need: { title?: bool, tags?: bool }, maxTags?: number }`.
  - `content` trimmed must be non-empty -> `400 {code:'empty_content'}`; longer than `MAX_CONTENT` ->
    `413 {code:'content_too_large'}`.
  - Default `need` is `{ title: true, tags: true }`; `maxTags` clamped to 1..10, default 5.
- Call `llm.suggestMetadata(...)`; on success `200 { title?, tags?, model: llmConfig.model }`.
- Map errors **exactly** like the timeline route: `llm_timeout` -> 504, `llm_rate_limited` -> 429,
  `llm_unparsable`/`llm_failed` -> 502. Reuse the existing error-to-response mapping by extracting it into one small
  `sendLlmError(res, e)` helper used by both routes - that is the only refactor allowed in the timeline path, and the
  existing timeline tests must still pass.
- Log one line per call: `gallery/suggest user=... need=title,tags ms=... ok=1` - never the content.

## 4. `lib/llm.js` - add `suggestMetadata`

- First extract the HTTP+JSON plumbing from `parseTimelineText` (`lib/llm.js:100-165`) into one private
  `async function chat(messages, { temperature, maxTokens })` that keeps the current behaviour exactly: the same
  `AbortController` timeout, the same 429/`!ok` handling (including reading `error.message` from the upstream body),
  the same `base_resp.status_code` check, no `thinking` field unless configured. `parseTimelineText` then calls it.
  Behaviour of `parseTimelineText` must not change - its tests are the proof.
- Add and export:

```
async function suggestMetadata({ content, needTitle, needTags, maxTags })
  -> { title?: string, tags?: string[] }
```

- System prompt: return **only** a JSON object, no prose, no code fences, shape
  `{"title":"...","tags":["..."]}`. Rules: the title is at most 60 characters, no surrounding quotes, no trailing
  period, in the **same language as the content**, and must not restate the first sentence verbatim; tags are 3-5
  short lowercase phrases (no `#`, no duplicates, no generic tags like `note`/`misc`), in the same language as the
  content. Omit `title` when only tags are requested and vice versa. Never invent facts that are not in the content.
- User message: the card content only, nothing else from the note.
- Request: `temperature: 0.3`, `max_completion_tokens: config.maxCompletionTokens` (keep 4096 - reasoning is counted
  against it on M3.1-Flash).
- Parse defensively: strip code fences, slice first `{` to last `}`, `JSON.parse` in try/catch. Validate: `title` ->
  string, trim, strip wrapping quotes, strip a trailing period, truncate to 200; `tags` -> array of strings, strip a
  leading `#`, trim, drop empties, dedupe case-insensitively, truncate each to 32, cap at `maxTags`. Requested-but-
  missing or wholly unusable output -> throw `llm_unparsable`.
- Never echo `content` into an error message.

## 5. `public/gallery.js` - browser pure module

UMD like `public/timeline.js` (`window.NotesGallery` + `module.exports`). No DOM access, no imports; functions that
need note state take it as arguments.

Exports:

- `PALETTE` (the same 12 keys, in the same order as `lib/gallery.js`) and `isPaletteKey`.
- `fallbackTitle(content, maxWords)` - byte-for-byte the same behaviour as the server copy (parity-tested).
- `previewText(content, maxChars = 180)` - collapse whitespace to single spaces, cut on a word boundary, append `…`
  when truncated; never cut a surrogate pair.
- `normalizeTags(input)` - from a comma/space/# separated string or array to a clean tag array (same rules as 2.1).
- `newCard({ title, content, tags, color, now, id })`, `updateCard(items, id, patch)`, `removeCard(items, id)` -

  `moveBy(items, id, delta)` for the keyboard/button path.
- `applySuggestion(items, id, { title, tags })` - fills only the fields that were requested and still empty; never
  overwrites a title the user typed.
- `summary(items)` -> `{ total, tagCount, colors }` for the toolbar.

Add `test/gallery.test.js` covering: preview truncation on word boundaries and CJK, `normalizeTags` edge cases,

## Do not

- Do not store gallery JSON in `note.content`; it is a derived mirror only.
- Do not add a new top-level `db` collection (the `loadDb` whitelist would drop it).
- Do not let a client-supplied `content` overwrite the mirror of a gallery note.
- Do not accept a gallery write from a client that does not send `gallery`.
- Do not grow the `kind === 'timeline'` checks into parallel `||` chains - use the dispatcher in 6.2.
- Do not send `thinking: {type:'disabled'}` - M3.1-Flash rejects it.
- Do not share the timeline rate-limit buckets with gallery suggestions.
- Do not send the whole note to the LLM - only the one card's content.
- Do not call the LLM on every keystroke; only when `Add` is pressed with a missing title or missing tags.
